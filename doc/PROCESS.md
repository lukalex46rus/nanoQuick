# Правила разработки nano_quick

## R1. Compile-time параметры
Всё, что известно при компиляции (пин, канал, режим, baud, делитель) — параметр шаблона,
не поле объекта. Объект существует только для состояния времени выполнения.
Конфигурация периферии — static-методы шаблонного struct, 0 байт RAM.

## R2. Неблокирующий API где возможно; polling-шины bounded-with-timeout
Периферия с разделением start()/poll()/value() (Adc, AdcStream, Spi-конвейер) — неблокирующая.
Шины последовательного обмена (I2c, Spi::transfer, Uart) — polling, блокировка ограничена
Deadline (toMs) и возвращает Err::Timeout. Ни один вызов не ждёт железо бесконечно:
либо таймаут, либо доказуемая ограниченность (Spi master при SPE=1 — максимум 8 SCK).
Контракт «только после init» документируется там, где таймаут не спасает (Uart put при TXEN=0).

## R3. Единый стиль ошибок
base::Status / base::Result<T> там, где операция может не удаться. void там, где не может.
Никаких bool/int8_t для ошибок. Err — фиксированный enum class uint8_t (base/Status.h).
Status — для I/O и готовности блока; чистые вычисления с определённым контрактом — без Status.

## R4. ISR минимальна
ISR ставит флаг / кладёт байт / инкрементирует счётчик. Вся логика в consumer/poll().
Максимум ~30 тактов полезной работы. ISR без Guard (прерывания запрещены на входе),
без ISR_NOBLOCK除非 измерена необходимость. Каждый .cpp с ISR явно включает <avr/interrupt.h>.

## R5. Модульная независимость
Модуль подключается include и не тянет соседей сверх указанных в «Зависит».
Проверяется по Δflash/RAM (meta.json бенча). Шапка модуля фиксирует зависимости.

## Шапка модуля (обязательна)
Каждый .h/.cpp начинается с блока:
  Платформа / Ресурсы / Предусл. / Контекст / Огранич. / Зависит.
Шапка описывает ФАКТИЧЕСКИЙ API, не желаемый. Если код расходится с шапкой — править код
или шапку в том же коммите. «Контекст» (main/ISR/один контекст) — обязательное поле:
большинство гонок ловится именно здесь.

## Конфигурация периферии
Любая настройка регистра AVR проверяется по таблице в datasheet ДО написания кода.
Не «по памяти», не «как обычно». Таблица, номер раздела, конкретная строка.
Комментарий у каждой конфигурации содержит ссылку на таблицу.
Примеры проверенных: Timer2 presc 64 = CS22 (табл. 17-9, не CS21|CS20=32);
SPI2X запись (табл. 19-2); TWI состояния 0x08/0x10/0x18/0x28/0x40/0x50/0x58;
USART UDRE=1 при пустом буфере (в т.ч. TXEN=0), TXC write-1-clear.

## Тулчейн (avr-gcc 7.3.0, gnu++11)
- C++ std-заголовки (<type_traits>, <algorithm> и др.) НЕ поставляются. Свой минимальный
  trait (hw::detail::is_integral) + builtin __is_enum. __is_integral появился в GCC 14 — не использовать.
- Внешние STL (ArduinoSTL/avr-libstdcpp) не тянем.
- unsigned int = 16 бит: округление вверх (v+K-1)/K считать в 32 битах, иначе wrap при v>=65533.
- volatile SFR: (void)SPSR — наблюдаемое чтение, компилятор не выкинет даже при -Os.
- PINx синхронизатор: чтение PINx сразу после записи PORTx/PINx даёт старое значение (0.5..1.5 такта).
  Для проверки только что установленного выхода читать PORTx. Бенчи gpio/mcu/pin_init — через PORTx.

## Замеры
Никаких чисел в контрактах без замера на железе или вывода из datasheet.
Одно изменение за прогон. Диагностический код убирается сразу после получения ответа.
Разделяющий тест вместо толкования данных.
Последнее/мин/макс фиксировать ВНУТРИ цикла потребления, не дополнительным take() после
дренажа буфера (после дренажа take() вернёт NotReady → ложный 0).

## Бенчмарк-инфраструктура
run_bench.ps1 + bench-spec.psd1 (расширение .psd1 обязательно для Import-PowerShellDataFile).
Режимы монитора: WaitAll (все Patterns, потолок HardCapSec + GraceSec), WaitSec (фикс), Visual.
Parse-Monitor берёт ПОСЛЕДНЕЕ совпадение regex (периодические бенчи: первая итерация включает setup).
Requires-бенчи (джампер/MCP) — Auto=$false, подтверждение в -Bench All или -Yes.
Результаты: results/<stamp>/<bench>/ (meta.json, compile.txt, upload.txt, monitor.txt[, nm.txt]);
results/<stamp>/summary.md (глаза), run.json (машина, сводный для диффов прогонов).
Expected — точные значения; Range — допуски (jitter/overhead); Info — не влияет на pass.

## Приёмка модуля
1. CONTRACTS.md обновлён (контракт = фактический API).
2. Шапка модуля заполнена и соответствует коду.
3. Бенчмарк в bench/ добавлен и пройден (PASS в meta.json).
4. Δflash/RAM зафиксированы в meta.json бенча (не в комментарии .ino).
5. Нет диагностического кода в продуктивных файлах.
6. RESOURCES.md обновлён если модуль занял периферию.

## Ограничения .ino (Arduino-препроцессор)
CLI генерирует прототипы свободных функций и вставляет их после #include.
Ломает: (а) шаблонные функции, (б) функции с пользовательскими типами в сигнатуре. Поэтому в .ino:
- шаблоны НЕ определяем как свободные функции;
- в сигнатурах только встроенные типы;
- шаблоны и сложные типы — в заголовках src/ (препроцессор их не трогает)
  либо как static-методы struct/class.
Библиотечные заголовки от этого бака не страдают.

## Имена в .ino (коллизии с core/libc)
Arduino.h тянет Stream/Print/String/Serial и макросы stdio (putc/puts).
Глобальные алиасы/функции в .ino НЕ должны совпадать с этими именами.
- using-алиасы типов: только уникальные имена (AdcPro, не Stream).
- функции вывода: не putc/puts/getchar (макросы stdio).
- сложные типы и шаблоны — в заголовках src/ или как static-методы struct.
Перед именованием сверяться: не занято ли имя в Arduino core / avr-libc.

## ISR и заголовки
Макрос ISR() определён в <avr/interrupt.h>. Каждый .cpp, определяющий ISR,
обязан включать его явно — не полагаться на транзитивные include.
Вектор (ADC_vect, TIMER2_COMPA_vect) приходит из avr/io.h через iom328p.h.
