# Правила разработки nano_quick

## R1. Compile-time параметры
Всё, что известно при компиляции (пин, канал, режим) — параметр шаблона,
не поле объекта. Объект существует только для состояния времени выполнения.

## R2. Неблокирующий API
Ни один публичный вызов не ждёт железо. Разделение start()/poll()/value().
Операции с ожиданием принимают Deadline и возвращают Err::Busy/Timeout.

## R3. Единый стиль ошибок
fn::Result там, где операция может не удаться. void там, где не может.
Никаких bool/int8_t для ошибок.

## R4. ISR минимальна
ISR ставит флаг / кладёт байт / инкрементирует счётчик. Вся логика в poll().
Максимум ~30 тактов полезной работы.

## R5. Модульная независимость
Модуль подключается флагом и не тянет соседей. Проверяется по Δflash/RAM.

## Конфигурация периферии
Любая настройка регистра AVR проверяется по таблице в datasheet ДО написания кода.
Не «по памяти», не «как обычно». Таблица, номер страницы, конкретная строка.
Комментарий у каждой конфигурации содержит ссылку на таблицу.

## Замеры
Никаких чисел в контрактах без замера на железе.
Одно изменение за прогон. Диагностический код убирается сразу после получения ответа.
Разделяющий тест вместо толкования данных.

## Приёмка модуля
1. CONTRACTS.md обновлён.
2. Бенчмарк в bench/ добавлен и пройден.
3. Δflash/RAM зафиксирован в комментарии бенчмарка.
4. Нет диагностического кода в продуктивных файлах.
