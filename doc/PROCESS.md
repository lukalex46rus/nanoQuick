# Правила разработки nano_quick

## R1. Compile-time параметры
Всё, что известно при компиляции (пин, канал, режим) — параметр шаблона,
не поле объекта. Объект существует только для состояния времени выполнения.

## R2. Неблокирующий API
Ни один публичный вызов не ждёт железо. Разделение start()/poll()/value().
Операции с ожиданием принимают Deadline и возвращают Err::Busy/Timeout.

## R3. Единый стиль ошибок
fn::Result там, где операция может не удаться. void там, где не может.
Никаких bool/int8_t для ошибок.

## R4. ISR минимальна
ISR ставит флаг / кладёт байт / инкрементирует счётчик. Вся логика в poll().
Максимум ~30 тактов полезной работы.

## R5. Модульная независимость
Модуль подключается флагом и не тянет соседей. Проверяется по Δflash/RAM.

## Конфигурация периферии
Любая настройка регистра AVR проверяется по таблице в datasheet ДО написания кода.
Не «по памяти», не «как обычно». Таблица, номер страницы, конкретная строка.
Комментарий у каждой конфигурации содержит ссылку на таблицу.

## Замеры
Никаких чисел в контрактах без замера на железе.
Одно изменение за прогон. Диагностический код убирается сразу после получения ответа.
Разделяющий тест вместо толкования данных.

## Приёмка модуля
1. CONTRACTS.md обновлён.
2. Бенчмарк в bench/ добавлен и пройден.
3. Δflash/RAM зафиксирован в комментарии бенчмарка.
4. Нет диагностического кода в продуктивных файлах.

## Ограничения .ino (Arduino-препроцессор)
CLI генерирует прототипы свободных функций и вставляет их после #include.
Это ломает: (а) шаблонные функции, (б) функции с пользовательскими типами
(struct/typedef/using) в сигнатуре. Поэтому в .ino:
- шаблоны НЕ определяем как свободные функции;
- в сигнатурах только встроенные типы;
- шаблоны и сложные типы — в заголовках src/ (препроцессор их не трогает)
  либо как static-методы struct/class.
Библиотечные заголовки от этого бака не страдают.

## Имена в .ino (коллизии с core/libc)
Arduino.h тянет классы Stream/Print/String/Serial и макросы stdio (putc/puts).
Глобальные алиасы/функции в .ino НЕ должны совпадать с этими именами.
- using-алиасы типов: только уникальные имена (AdcPro, не Stream).
- функции вывода: не putc/puts/getchar (макросы stdio).
- сложные типы и шаблоны — в заголовках src/ или как static-методы struct.
Перед именованием сверяться: не занято ли имя в Arduino core / avr-libc.

## ISR и заголовки
Макрос ISR() определён в <avr/interrupt.h>. Каждый .cpp, определяющий ISR,
обязан включать его явно — не полагаться на транзитивные include из других
заголовков. Вектор (ADC_vect, TIMER2_COMPA_vect и т.д.) приходит из avr/io.h
через iom328p.h.

## Замер значений в consumer-цикле
Последнее/мин/макс значения фиксировать ВНУТРИ цикла потребления, а не
дополнительным take() после вычерпывания буфера: после дренажа буфер пуст
и take() вернёт NotReady. Иначе получаем ложный 0.
